# Legacy Nexus Audit Reconciliation

**Input reviewed:** user-provided `dc_bot_rough(1).txt`, a technical audit/catalog of a Python 3.10+/Pycord, `aiosqlite`, `aiohttp` Discord bot called Nexus.  
**Important boundary:** the actual Python repository was not attached. This is a disposition of the _reported_ features and architectural claims, not a source-code audit or verified runtime result. Each item must be reconciled against source before treating it as a migration checklist.

## 1. Disposition vocabulary

- **Retain outcome, rebuild implementation:** the user value is good but the legacy technical approach is not the target.
- **Retain with safeguards:** implement after adding production controls and tests.
- **Replace:** a safer/simpler target achieves the need better.
- **Defer:** useful after P0 or after business/policy decision.
- **Drop unless justified:** workaround or capability that has no clear need in the new product.

## 3. Migration method

1. Obtain the actual source repository and note commit/release version.
2. Inventory active command registrations, aliases, event handlers, UI custom IDs, database tables, dashboard routes and environment variables.
3. For each reported legacy item, mark **present**, **absent**, **partial**, **dead/unused**, **broken**, or **uncertain** using direct source evidence and tests.
4. Map each retained user outcome to the new domain capability and acceptance tests.
5. Avoid mechanical file-by-file porting; separate domain rules from Discord and web adapters.
6. Migrate data only if existing users/config need it. Create an explicit export/transform/validate/import plan with backup and rollback. Do not carry insecure session/passcode structures forward.
7. Compare old and new command/user outcomes with staging tests, then document intentionally removed behavior.

## 4. Must-not-carry-forward assumptions

- Administrator access or membership in one staff role automatically means full bot access.
- A private Discord log channel alone is a sufficient audit system.
- A message being queued means it has been sent.
- A private DM is guaranteed to arrive.
- In-memory poll votes, timers or custom view instances are durable across restart.
- Channel deletion is the same thing as ticket closure.
- Hiding dashboard controls is security.
- A single global developer ID embedded in code is a production privilege model.
- A fallback dispatcher can replace supported application-command registration without trade-offs.
- Presence, Message Content or all member data should be enabled just because the legacy version used them.
